# 商业模式成立性与导出数据价值验证

文档日期：2026-05-26  
公司方向：纤维织物触觉传感器、触觉鞋垫、触觉全身衣、触觉手套、机器人触觉皮肤  
问题：这个商业模式成立吗？导出的数据真的有用吗？  
使用 Skill：`business-model` + `identify-assumptions-new` + `prioritize-assumptions`

## 1. 先给判断

这个商业模式**有机会成立**，但前提不是“我们能导出数据”，而是：

> 你们导出的数据能让机器人/世界模型客户更快训练、更准确评测、更少返工，并且客户愿意反复采集和持续购买。

换句话说：

| 错误理解 | 正确理解 |
|---|---|
| 我们卖传感器 | 我们卖物理世界触觉数据采集能力 |
| 我们导出 CSV/JSON | 我们交付可训练、可回放、可标注、可复现的数据集 |
| 客户拿到数据就会用 | 客户需要 schema、质量报告、样例模型、导出工具 |
| 数据越多越好 | 可对齐、可解释、可训练的数据才有价值 |
| 商业模式是卖硬件 | 初期是硬件 + PoC，长期是数据采集系统 + 软件平台 + 数据服务 |

真正成立的商业模式应该是：

> 硬件采集套件 + 本地采集软件 + 同步回放/标注工具 + 数据导出格式 + PoC 服务 + 后续数据平台订阅/私有部署。

## 2. 导出的数据到底有没有用

### 2.1 有用的条件

导出的数据只有满足这些条件才有用：

| 条件 | 为什么重要 |
|---|---|
| 多模态同步 | 视频、触觉、音频、动作错位，训练价值会大幅下降。 |
| 有明确任务 | 只采“人在动”不够，要知道在抓取、行走、递物、碰撞还是滑移。 |
| 有事件标签 | 接触开始、接触结束、滑移、过压、抓取成功、步态阶段。 |
| 有质量指标 | 客户要知道这条数据有没有丢帧、断连、饱和、错位。 |
| 有统一 schema | 客户算法团队能稳定读取和训练。 |
| 有 baseline | 至少证明“视频 + 触觉”比“只有视频”在某个任务上更好。 |
| 可复采 | 同一任务可以重复采集，形成可扩大数据集。 |

如果只是导出：

```text
video.mp4 + pressure.csv
```

那价值不稳定。客户可能看完说“挺有意思”，但不知道怎么训练。

如果导出的是：

```text
session_id
video
tactile_stream
audio
timestamps
events
quality_report
task_label
success/failure
export_to_lerobot / pytorch
```

那就更接近 AI/机器人团队能用的数据资产。

### 2.2 哪些数据最有用

| 数据 | 有用性 | 适合训练/评测什么 |
|---|---|---|
| 第一人称视频 + 手套触觉 | 很高 | 抓取成功、滑移、接触力、物体软硬、操作策略 |
| 第一人称视频 + 鞋垫触觉 | 高 | 步态阶段、重心转移、负重行走、站稳/失衡 |
| 第一人称视频 + 全身衣接触 | 高 | 人机接触安全、碰撞、身体接触位置、压力持续时间 |
| 机器人相机 + 机器人触觉皮肤 | 很高 | 机器人抓取、碰撞检测、协作搬运、安全接触 |
| 只有触觉没有视频 | 中 | 适合压力分析，但对世界模型价值下降 |
| 只有视频没有触觉 | 已有很多替代 | 你们差异化弱 |

结论：

> 数据不是因为“触觉”天然有用，而是因为它补上了视觉在接触、压力、滑移、重心、安全方面的盲区。

## 3. Business Model Canvas

### 3.1 Customer Segments

优先客户不是所有机器人公司，而是：

1. 人形机器人公司。
2. 机器人基础模型 / VLA 模型团队。
3. 世界模型 / 具身智能数据团队。
4. 机器人实验室和高校研究团队。
5. 后续扩展到医疗康复、工业协作、农业采摘。

第一批最适合：

> 正在做真实世界数据采集、模仿学习、机器人操作、接触安全的人形机器人/具身智能团队。

### 3.2 Value Proposition

你们交付的价值不是“触觉硬件”，而是：

> 让客户获得视觉看不到的物理交互监督信号：接触、压力、滑移、重心、碰撞和安全边界。

客户买你们，是为了：

1. 采集更高质量的机器人训练数据。
2. 建立自己的多模态数据壁垒。
3. 验证视觉模型在物理接触上的盲区。
4. 训练/评测抓取、行走、人机接触安全等任务。
5. 降低自研触觉采集系统的时间成本。

### 3.3 Channels

| 阶段 | 渠道 |
|---|---|
| 初期 | 创始人直销、机器人公司 PoC、高校实验室、投资人/展会 Demo |
| 中期 | 与机器人平台、相机/动捕、仿真平台合作 |
| 后期 | SDK、数据平台、开发者文档、行业 benchmark |

### 3.4 Customer Relationships

初期应该是高接触销售：

1. 联合定义采集任务。
2. 到客户现场或远程协助采集。
3. 帮客户导出数据。
4. 帮客户做一个 baseline 对比。

不能一开始就指望客户自助购买、自助集成、自助训练。

### 3.5 Revenue Streams

| 收入方式 | 是否建议 | 说明 |
|---|---|---|
| 硬件套件销售 | 建议 | 第一阶段现金流来源，包含手套、鞋垫、全身衣、同步盒/采集端。 |
| PoC 项目费 | 强烈建议 | 客户需要你们帮他证明数据价值，不能免费做太多。 |
| 软件授权 | 建议 | 采集软件、回放、标注、导出工具。 |
| 数据平台订阅 | 中后期 | 有足够客户和数据量后成立。 |
| 私有部署 | 建议 | 机器人/大模型客户通常重视数据安全。 |
| 数据服务/联合数据集 | 谨慎 | 数据权属和隐私复杂，后期再做。 |
| 按数据小时计费 | 可探索 | 适合“代采集”或“数据集构建服务”。 |

更现实的初期商业模式：

```text
硬件套件  +  PoC 服务费  +  软件工具授权
```

中期商业模式：

```text
采集系统  +  私有数据平台  +  数据集导出/标注/质量分析服务
```

### 3.6 Key Activities

1. 硬件采集稳定性。
2. 多模态同步。
3. 触觉数据标定。
4. 同步回放和标注。
5. 数据导出工具。
6. 客户 PoC 成功案例。
7. baseline 模型/评测。

### 3.7 Key Resources

1. 纤维织物触觉传感器技术。
2. 手套、鞋垫、全身衣硬件。
3. 采集软件和数据 schema。
4. 同步回放/标注工具。
5. 数据质量评估能力。
6. 机器人/AI 客户案例。

### 3.8 Key Partners

1. 人形机器人公司。
2. 高校机器人实验室。
3. 第一人称相机/AR 眼镜厂商。
4. ROS / LeRobot / Hugging Face 生态。
5. 仿真平台和机器人开发平台。

### 3.9 Cost Structure

主要成本：

1. 硬件 BOM 和生产。
2. 设备调试、标定、售后。
3. 软件研发。
4. 客户 PoC 支持。
5. 数据存储和计算。
6. 数据安全和私有部署。

最大风险成本：

> 如果每个客户都要大量定制，毛利会被项目交付吃掉。

因此必须尽早标准化：

1. 采集套件。
2. 数据 schema。
3. 标定流程。
4. 回放工具。
5. 导出格式。

## 4. 最大风险假设

按 `identify-assumptions-new` skill 拆解，当前最危险的假设有 8 类。

| 风险类别 | 关键假设 | 为什么危险 |
|---|---|---|
| Value | 客户认为触觉数据能提升模型/机器人能力 | 如果客户只觉得“有趣”，但不认为必要，就不会付费。 |
| Value | 视觉 + 触觉比纯视觉有可量化提升 | 这是核心价值证据。 |
| Usability | 客户算法团队能读懂并使用导出的数据 | 如果格式复杂、文档不足，数据会被闲置。 |
| Viability | 客户愿意为 PoC/套件/软件付费 | 没有付费意愿，商业模式不成立。 |
| Viability | 硬件 + 服务交付后毛利可接受 | 如果每单都重度定制，会变成低毛利项目公司。 |
| Feasibility | 多模态同步和数据质量能稳定达标 | 同步不准，数据训练价值会下降。 |
| Go-to-Market | 能找到愿意试用的机器人/模型客户 | 客户渠道不足会拖慢验证。 |
| Strategy | 巨头不会很快自研替代全部系统 | 机器人公司可能自研传感器或数据栈。 |
| Team | 团队既能做硬件，又能做数据平台和客户 PoC | 这是硬件 + 软件 + AI 数据的复合能力。 |

## 5. 假设优先级

按 `prioritize-assumptions` skill，先测高影响、高风险假设。

| 优先级 | 假设 | 影响 | 风险 | 应该怎么测 |
|---|---|---:|---:|---|
| P0 | 视频 + 触觉是否比纯视频更能判断滑移/抓稳/接触安全 | 高 | 高 | 做 3 个任务的对比实验 |
| P0 | 客户是否愿意为 PoC 付费 | 高 | 高 | 拿 Demo 找 5-10 家客户谈付费 PoC |
| P0 | 导出数据客户能不能用 | 高 | 高 | 给客户一份样例 dataset + schema + notebook |
| P0 | 采集同步质量是否足够 | 高 | 中高 | 每条 session 出同步误差和丢帧报告 |
| P1 | 全身衣是否是强购买理由 | 中高 | 中高 | A/B 测试“手套+鞋垫” vs “加全身衣”的客户反应 |
| P1 | 客户是否需要平台而不是只要文件 | 中高 | 中 | 观察 PoC 后客户是否频繁检索/标注/复采 |
| P1 | 机器人穿戴版本是否比人穿戴更有商业价值 | 中高 | 高 | 找 2 家机器人客户做触觉皮肤 PoC |
| P2 | 数据平台订阅是否成立 | 高 | 高 | 等 3 个以上 PoC 后再验证，不要太早做平台 |

## 6. 最小验证实验

### 实验 1：数据是否真的有用

目标：

> 证明视觉 + 触觉在某个任务上比纯视觉更好。

任务：

1. 抓杯子/海绵/布料。
2. 制造抓稳、滑移、过轻、过重四类情况。
3. 采集第一人称视频 + 手套触觉。

对比：

| 输入 | 任务 |
|---|---|
| 只有视频 | 判断是否抓稳、是否滑移 |
| 视频 + 触觉 | 判断是否抓稳、是否滑移 |

成功标准：

> 视频 + 触觉的判断准确率明显高于纯视频，或者能更早发现滑移。

哪怕先不用大模型，用简单规则/小模型也可以。

### 实验 2：客户是否真的想要

目标：

> 证明客户不只是觉得有意思，而是愿意给场景、给数据、给钱。

做法：

1. 准备 2 分钟 Demo 视频。
2. 准备一份样例 dataset。
3. 找 10 家目标客户访谈。
4. 不问“你觉得怎么样”，直接问：
   - 你们现在怎么采机器人训练数据？
   - 有没有接触/滑移/压力相关失败？
   - 这类数据能不能进入你们训练/评测流程？
   - 如果我们帮你们做一个 PoC，你们愿不愿意付费？

成功标准：

> 10 家里至少 3 家愿意提供真实任务，至少 1-2 家愿意进入付费 PoC。

### 实验 3：导出数据客户能不能用

目标：

> 验证导出的数据格式不是自嗨。

交付：

1. `metadata.json`
2. `video.mp4`
3. `tactile.jsonl / parquet`
4. `events.jsonl`
5. `quality_report.json`
6. Python notebook
7. 数据说明文档

成功标准：

> 客户算法工程师能在 1 小时内读取数据、画出触觉曲线、按时间对齐视频帧，并跑一个简单判断任务。

### 实验 4：商业模式是否能收钱

目标：

> 判断收入模式应该先卖硬件、PoC、软件，还是数据服务。

报价测试：

| 方案 | 内容 | 验证问题 |
|---|---|---|
| A | 硬件套件一次性销售 | 客户是否愿意买设备自采 |
| B | 硬件 + PoC 服务费 | 客户是否愿意为结果付费 |
| C | 代采集数据服务 | 客户是否只想要数据 |
| D | 私有平台授权 | 客户是否有长期数据管理需求 |

第一阶段最可能成立的是：

> B：硬件 + PoC 服务费。

因为客户还不知道怎么用触觉数据，你们需要一起帮他证明价值。

## 7. 什么情况下商业模式成立

满足下面 5 个条件，就基本成立：

1. 客户承认视觉在接触物理上不够。
2. 视频 + 触觉在至少 1-2 个任务上有量化提升。
3. 客户算法团队能使用你们导出的数据。
4. 客户愿意付费做 PoC，而不只是免费试用。
5. PoC 能沉淀成通用产品能力，而不是每次重做一套。

## 8. 什么情况下不成立

如果出现下面情况，就要谨慎：

1. 客户只愿意免费试用，不愿意付费 PoC。
2. 客户说“这个数据有意思”，但没人把它接进训练/评测流程。
3. 你们每个项目都要大量定制，无法标准化。
4. 触觉数据相比纯视觉没有明显提升。
5. 同步、标定、数据质量长期不稳定。
6. 客户最终只把你们当普通压力传感器供应商压价。

## 9. 我建议的商业模式路径

### 第一阶段：卖 PoC，不卖平台

产品：

> 视觉 + 全身触觉同步采集 PoC 套件。

收入：

1. 硬件押金/销售。
2. PoC 服务费。
3. 数据整理和导出费用。

目标：

> 证明数据有用，拿到 2-3 个真实客户场景。

### 第二阶段：卖标准采集系统

产品：

> EgoTouch / FullBody Touch 数据采集系统。

收入：

1. 硬件套件。
2. 采集软件授权。
3. 回放/标注/导出工具授权。
4. 私有部署。

目标：

> 客户能自己持续采集，形成复采。

### 第三阶段：卖数据平台

产品：

> 视觉 + 触觉机器人数据平台。

收入：

1. 平台订阅。
2. 私有化部署。
3. 数据质量分析。
4. 数据集版本管理。
5. 标注和导出服务。

目标：

> 从一次性硬件销售变成长期数据基础设施。

## 10. 现在最该做的 30 天验证

不要先做完整平台。先做这 4 件事：

1. 做 20 条样例 session：
   - 抓取。
   - 滑移。
   - 负重行走。
   - 人机/人与物接触。

2. 做一个最小 dataset：
   - 视频。
   - 手套/鞋垫/全身衣触觉。
   - 时间戳。
   - 事件标签。
   - 质量报告。

3. 做一个小实验：
   - 纯视频判断滑移/抓稳。
   - 视频 + 触觉判断滑移/抓稳。
   - 看是否有提升。

4. 找 10 家客户验证：
   - 人形机器人公司。
   - 机器人基础模型团队。
   - 具身智能实验室。
   - 仓储/工厂自动化团队。

30 天后只看三个结果：

| 结果 | 判断 |
|---|---|
| 数据实验有提升 | 说明数据有技术价值 |
| 客户愿意给真实场景 | 说明有需求 |
| 客户愿意付费 PoC | 说明商业模式有机会成立 |

## 11. 最终判断

现在可以继续推进，但要避免两个误区：

1. 不要把商业模式建立在“我们能导出数据文件”上。
2. 不要一开始就重投入数据平台。

正确路径是：

> 先证明导出的数据能让客户完成一个原来做不好的判断任务，再证明客户愿意为这个能力付费，然后再把采集、回放、标注、导出沉淀成平台。

如果你们能做到“视频 + 触觉比纯视频在抓取、滑移、步态、人机接触安全上更有用”，这个商业模式就有成立基础。
