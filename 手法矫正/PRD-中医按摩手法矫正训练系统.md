# PRD-中医按摩手法矫正训练系统

## 1. Summary

本文档定义一个用于中医按摩、推拿手法训练的数据采集与矫正系统。系统以贴在受力面上的压力阵列为核心传感器，采集真实受力位置、压力大小、接触面积、压力轨迹和节奏，用于建立专家标准、训练模型，并给新手提供可解释的手法矫正反馈。

第一版产品不以手套或手部 IMU 作为主传感方案。手部 IMU 只作为可选辅助，用于解释手腕姿态、动作抖动和冲击发力，不用于判断真实受力位置。

## 3. Background

### 3.1 背景

中医按摩和推拿手法依赖经验传承。老师通常通过观察、触摸和口头指导来纠正学生。这个过程存在几个问题：

- 新手不知道自己的力到底多大；
- 新手不知道力是否落在正确位置；
- 老师难以量化“节奏不稳”“发力太冲”“接触不实”；
- 不同老师的评价口径可能不同；
- 学生课后难以独立训练和复盘。

压力阵列可以把手法过程转成连续数据。它能记录真实受力面的压力分布、总压力、接触面积、压力中心和轨迹。这些数据可以用于建立专家标准，也可以用于新手训练反馈。

### 3.2 为什么现在做

压力阵列、柔性传感器、嵌入式采集和边缘计算已经更成熟。相比过去只靠单点力值，现在可以采集一整片受力区域的连续变化。AI 时序模型也可以处理完整动作过程，而不是只判断某一帧。

### 3.3 关键认知

手法不是一个静态姿势，而是一个连续过程。

一次手法至少包含：

- 按压位置；
- 压力大小；
- 加力过程；
- 卸力过程；
- 接触面积变化；
- 压力中心移动；
- 节奏频率；
- 周期稳定性。

所以数据集的基本单位应是“一段完整手法 episode”，而不是单帧压力图。

## 4. Objective

### 4.1 产品目标

建立一个面向中医按摩和推拿训练的手法量化与矫正系统。系统需要帮助老师和学生完成：

- 采集专家标准手法；
- 采集学生练习手法；
- 识别手法过程中的力度、位置、面积、轨迹和节奏问题；
- 给出可解释的矫正建议；
- 沉淀可训练模型的数据集。

### 4.2 不做什么

第一版不做：

- 疾病诊断；
- 疗效判断；
- 医疗处方建议；
- 复杂全身动作捕捉；
- 以手套作为主要受力判断依据；
- 以 IMU 判断真实受力位置。

### 4.3 Key Results

| KR | 指标 |
|---|---|
| KR1 | 完成 1 种核心手法的专家数据采集，至少 500 段有效 episode |
| KR2 | 完成新手数据采集，至少 1000 段有效 episode |
| KR3 | 压力阵列可稳定输出总压力、接触面积、压力中心和轨迹 |
| KR4 | 系统可识别至少 4 类错误：力度过大/过小、节奏不稳、位置偏移、接触面积异常 |
| KR5 | 第一版矫正反馈能被专家判定为有用，有用率达到 80% 以上 |
| KR6 | 模型评估必须按操作者划分训练集和测试集，避免数据泄漏 |

## 5. Market Segment(s)

### 5.1 目标用户

| 用户 | 主要任务 | 痛点 |
|---|---|---|
| 中医推拿学校 | 教学、考试、训练 | 难以量化学生手法 |
| 康复训练机构 | 技师培训和考核 | 老师指导成本高 |

| 传感器厂商 | 行业方案落地 | 需要可演示、可销售的应用场景 |

### 5.2 第一优先级市场

第一阶段建议面向“中医推拿教学和培训场景”，而不是直接进入临床诊疗。

原因：

- 教学场景更容易验证价值；
- 风险和合规压力更低；
- 专家和学生都能参与数据采集；
- 对“手法标准化”和“训练反馈”需求明确；
- 更适合先做 MVP。

### 5.3 使用场景

典型场景：

1. 老师在训练垫或仿体上完成标准手法采集；
2. 学生按同样部位和手法练习；
3. 系统实时显示力度、位置、面积、节奏；
4. 系统指出偏差；
5. 学生根据反馈重复练习；
6. 老师查看训练记录和趋势。

## 7. Solution

### 7.1 产品形态

第一版产品建议由三部分组成：

| 模块 | 说明 |
|---|---|
| 受力面压力阵列 | 贴在皮肤、仿体或训练垫上，采集真实受力 |
| 数据采集与训练软件 | 记录数据、显示实时指标、管理训练任务 |
| 手法矫正算法 | 计算指标、对比专家模板、输出矫正建议 |

可选模块：

| 模块 | 说明 |
|---|---|
| 手腕/手背 IMU | 仅用于辅助解释姿态，不作为真实受力判断依据 |
| 同步视频 | 用于标注、复盘和模型校验 |
| 剪切力传感器 | 后续用于判断切向力和旋转力矩 |

### 7.2 传感器原则

#### 7.2.1 压力阵列是核心

压力阵列应放在被按压的一侧，包括：

- 人体皮肤表面；
- 仿人体皮肤训练模型；
- 训练垫；
- 标准化手法采集平台。

原因：

- 真实受力发生在被按压侧；
- 只有受力面传感器能准确知道压力落在哪里；
- 手套无法可靠知道患者皮肤上的精确受力位置；
- 手套会带来滑移、褶皱和手感干扰；
- 手套数据更适合分析操作者手部发力，不适合作为真实落点依据。

#### 7.2.2 IMU 是辅助，不是主传感

IMU 可以放在手腕或手背，用于采集：

- 手腕角度；
- 手掌倾斜趋势；
- 角速度；
- 加速度；
- 抖动；
- 冲击式发力；
- 动作节奏。

IMU 不能直接判断：

- 真实按压位置；
- 皮肤上的压力分布；
- 接触面积；
- 压力中心；
- 受力面轨迹。

所以第一版可以没有 IMU。若加入 IMU，也只用于解释压力异常背后的动作原因。

### 7.3 核心用户流程

#### 7.3.1 专家建模流程

```text
选择手法
  -> 选择训练部位
  -> 专家完成 8-10 秒标准手法
  -> 系统采集压力阵列数据
  -> 自动计算力度、面积、COP、频率、轨迹
  -> 专家确认样本是否有效
  -> 样本进入专家模板库
```

#### 7.3.2 学生训练流程

```text
选择手法和部位
  -> 学生开始练习
  -> 系统实时显示压力分布和关键指标
  -> 练习结束后生成评分
  -> 系统给出主要问题和建议
  -> 学生重复训练
```

#### 7.3.3 老师复盘流程

```text
选择学生
  -> 查看训练记录
  -> 对比专家模板
  -> 查看错误分布
  -> 给出人工点评
  -> 导出训练报告
```

### 7.4 Key Features

#### F1. 实时压力热力图

显示受力面的实时压力分布。

必须支持：

- 颜色显示压力强弱；
- 显示当前接触区域；
- 显示压力中心；
- 显示总压力或估算总力；
- 保存原始帧数据。

#### F2. 手法 episode 采集

一次训练以完整 episode 保存，默认 8-10 秒。

必须保存：

- 原始压力矩阵序列；
- 时间戳；
- 手法类型；
- 训练部位；
- 操作者；
- 专家/学生身份；
- 采样率；
- 设备编号；
- 标注信息。

#### F3. 力度量化

计算：

- 峰值压力；
- 平均压力；
- 总压力；
- 力度波动；
- 加力速度；
- 卸力速度；
- 力冲量。

输出示例：

```text
本次力度偏高，峰值压力高于专家区间 22%。
```

#### F4. 位置和轨迹量化

计算：

- 压力中心 COP；
- COP 轨迹；
- 轨迹长度；
- 轨迹方向；
- 与专家模板的偏移距离；
- 是否超出目标区域。

输出示例：

```text
压力中心整体向右侧偏移，建议调整掌根落点。
```

#### F5. 接触面积量化

计算：

- 接触面积；
- 接触面积变化；
- 局部高压区域；
- 接触是否突然丢失；
- 是否存在点状硬压。

输出示例：

```text
接触面积偏小，局部压力集中，建议扩大掌面接触。
```

#### F6. 节奏和周期分析

适用于滚法、揉法等周期性手法。

计算：

- 周期频率；
- 单周期时长；
- 峰值间隔；
- 周期稳定性；
- 前后半段节奏漂移。

输出示例：

```text
节奏不稳定，第 4-7 秒周期波动明显。
```

#### F7. 专家模板对比

系统应支持建立专家模板。

模板包含：

- 压力范围；
- 接触面积范围；
- COP 轨迹范围；
- 频率范围；
- 周期稳定性范围；
- 典型错误阈值。

第一版可以先使用规则和统计区间。后续再使用机器学习模型。

#### F8. 矫正建议生成

矫正建议必须可解释。

不接受只输出：

```text
得分 65 分
```

必须输出：

```text
主要问题：力度偏高，接触面积偏小。
建议：减小下压力，扩大掌面接触，保持压力中心在目标区域内。
```

#### F9. 数据集管理

系统需要支持：

- 样本查询；
- 样本回放；
- 样本标注；
- 无效样本剔除；
- 专家样本锁定；
- 数据导出；
- 模型训练集生成。

### 7.5 技术方案

#### 7.5.1 数据采集

建议采样率：

| 数据 | 建议 |
|---|---:|
| 压力阵列 | 50-100 Hz |
| 可选 IMU | 100-200 Hz |
| 可选视频 | 30-60 FPS |

第一版压力阵列采样率建议不低于 50 Hz，目标为 100 Hz。

#### 7.5.2 数据结构

每条训练样本为一个 episode：

```json
{
  "episode_id": "rolling_0001",
  "technique": "rolling",
  "body_part": "lower_back",
  "operator_id": "student_001",
  "operator_level": "student",
  "duration_sec": 10,
  "sampling_rate_hz": 100,
  "quality_score": 72,
  "error_labels": ["force_too_high", "contact_area_too_small"],
  "sensor_files": {
    "pressure": "pressure.parquet",
    "video": "video.mp4"
  }
}
```

#### 7.5.3 数据处理

处理流程：

```text
原始压力矩阵
  -> 去噪和标定
  -> 计算总压力
  -> 计算接触面积
  -> 计算压力中心 COP
  -> 计算轨迹
  -> 检测周期
  -> 提取特征
  -> 对比专家模板
  -> 输出评分和建议
```

#### 7.5.4 模型路线

MVP：

- 规则指标；
- 专家统计区间；
- 阈值判断；
- 简单分类模型。

产品初版：

- XGBoost / Random Forest；
- TCN / LSTM；
- CNN + 时序模型，用于压力阵列序列。

进阶版本：

- Transformer；
- 多专家模板聚类；
- 个性化训练模型；
- 压力阵列 + IMU 多模态融合。

### 7.6 数据量要求

#### MVP

建议先做 1 个手法，例如滚法或揉法。

```text
专家：10 人 x 50 段 = 500 段
学生：20 人 x 50 段 = 1000 段
合计：1500 段 episode
```

#### 产品初版

```text
3-5 种手法
每种手法 1000-3000 段
每种错误类型 200-500 段
至少 30 名操作者
```

#### 商用版本

```text
每种手法 5000 段以上
50-100 名操作者
多专家、多批次、多场景
测试集按操作者独立划分
```

### 7.7 Assumptions

当前假设：

- 受力面压力阵列可以稳定贴合皮肤、仿体或训练垫；
- 压力阵列的标定精度足够支持训练反馈；
- 专家能定义每种手法的标准区间；
- 学生愿意根据数据反馈重复训练；
- 第一阶段以教学训练为主，不进入临床诊疗判断；
- 部分手法涉及切向力和旋转力，普通压力阵列可能只能近似判断方向。

需要验证：

- 压力阵列是否会明显影响真实手感；
- 不同人体部位曲面是否影响采集质量；
- 贴在皮肤上的方案是否稳定、卫生、可重复；
- 训练垫或仿体能否代表真实人体；
- 专家之间的标准差有多大；
- 单纯压力阵列是否足够支撑第一版矫正。

## 9. 关键风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 压力阵列影响手感 | 用户不愿使用 | 优先测试薄膜、仿体和训练垫方案 |
| 皮肤贴合不稳定 | 数据噪声大 | 优先做标准训练垫/仿体 MVP |
| 专家标准不一致 | 模板难建立 | 使用多专家区间，不用单一标准值 |
| 只测法向压力 | 难判断切向力 | 先做力度、面积、轨迹，后续加入剪切力 |
| 数据泄漏 | 模型评估虚高 | 按操作者划分训练集和测试集 |
| 反馈不可解释 | 用户不信任 | 所有评分必须对应具体指标 |

## 10. MVP 范围建议

第一版只做：

- 1 个手法：滚法或揉法；
- 1 个标准训练部位；
- 受力面压力阵列；
- 实时压力热力图；
- episode 采集；
- 力度、面积、COP、轨迹、频率；
- 专家模板对比；
- 4 类错误反馈。

第一版不做：

- 临床诊断；
- 多部位复杂训练；
- 手套作为主采集方案；
- 多 IMU 动作捕捉；
- 切向力精确判断；
- 端到端大模型。

## 11. 一句话产品定义

这是一个基于受力面压力阵列的中医按摩手法训练系统，用真实压力分布和连续时序数据，把专家手法变成可学习、可量化、可纠正的训练标准。
